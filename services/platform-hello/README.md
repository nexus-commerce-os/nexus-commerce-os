# `platform-hello` — the P0.1 pipeline canary

> **This is the P0.1 pipeline canary, not a product service.** It has **no business logic**.
> Its only job is to prove the whole platform pipeline works end-to-end — chart → image →
> signature/admission → deploy → probes → metrics scrape → traces/logs landing in the
> observability domain. Delete-me-later energy, except we keep it as a permanent smoke-test
> workload.

- **Purpose:** walking-skeleton service that exercises every platform contract from
  [ADR-0010](../../docs/adr/ADR-0010-platform-principles.md) (#5 health, #6 metrics) and
  [docs/10 §6–7](../../docs/10-deployment-architecture.md), so P0.1 infra is validated by a
  real running workload rather than by inspection.
- **Owner:** Platform Engineering + SRE.
- **Dependencies:** Go 1.22 (build); the [`nexus-common`](../../infrastructure/kubernetes/charts/nexus-common)
  library chart (deploy); the OTel Collector in the `observability` namespace (trace/metric
  export — off the critical path, so its absence only disables export, never serving).

## Endpoints (the org health/metrics contract)

| Path | Port | Kind | Behavior |
|------|------|------|----------|
| `/` | 8080 | OTel-traced | returns `nexus platform-hello ok`; opens a server span (`otelhttp`) + child span |
| `/healthz` | 8080 | **liveness** | 200 while the process is up |
| `/readyz` | 8080 | **readiness** | 200 only after warm-up **and** the dependency-check stub passes; 503 otherwise (gates traffic + backs canary analysis) |
| `/metrics` | 9090 | Prometheus | golden-signal metrics (`platform_hello_http_requests_total`, `..._request_duration_seconds`, `..._build_info`) on a **separate port** so scrape traffic is isolated |

The readiness dependency check (`checkDependencies` in [`main.go`](main.go)) is a **stub** — a real
service verifies DB/cache/downstream health here. Keeping the shape proves the pattern
([docs/10 §7](../../docs/10-deployment-architecture.md): dependency-health backs failover; §4.1).

## Build & run locally

```bash
go test ./...                 # unit tests: root, healthz, readyz cold/warm, route wiring
go build -o platform-hello .
HTTP_PORT=8080 METRICS_PORT=9090 ./platform-hello
curl -s localhost:8080/            # nexus platform-hello ok
curl -s localhost:8080/healthz     # ok
curl -s localhost:8080/readyz      # ready
curl -s localhost:9090/metrics     # prometheus exposition
```

> `go.sum` is generated by CI (`go mod download`) — Go is not vendored in this scaffold.

## Container

Multi-stage → `gcr.io/distroless/static-debian12:nonroot`, uid/gid **65532**, no shell, static
`CGO_ENABLED=0` binary. Read-only root FS and `drop: [ALL]` are applied by the chart at runtime.
Base image is pinned-by-digest + ECR-mirrored in real builds; image is cosign-signed with an
SBOM + SLSA provenance in CI ([docs/10 §3/§6](../../docs/10-deployment-architecture.md)).

```bash
docker build --build-arg APP_VERSION=0.1.0 -t nexus/platform-hello:dev .
```

## Deploy (inherits everything from nexus-common)

```bash
helm dependency build helm
helm template hello helm | kubectl apply --dry-run=client -f -
```

The [`helm/`](helm) chart sets only image, tiny resources, pool, and OTel endpoint — all
probes, securityContext, HPA, PDB, NetworkPolicy, and ServiceMonitor come from the library
chart. This same chart is what the Kustomize base + ArgoCD Applications point at.
