# infrastructure/security/supply-chain — signing, SBOM, provenance, admission

> **Purpose.** Defines how every deployable artifact becomes **trustworthy by construction**:
> keyless signing, a Software Bill of Materials, SLSA provenance, and the admission control
> that refuses anything unsigned or non-compliant.
> **Owner.** `@nexus/cloud-security` + `@nexus/devsecops`.
> **Dependencies.** cosign (Sigstore Fulcio/Rekor), Syft, GitHub OIDC (keyless identity),
> the CI Build job ([`.github/workflows/ci.yml`](../../../.github/workflows/ci.yml) stage 14),
> the CD verify step ([`cd-prod.yml`](../../../.github/workflows/cd-prod.yml)), and the
> in-cluster admission controller.

Certified by docs/10 §2 (SBOM gate), §3 (image signing & provenance, admission control),
docs/08 §5.3 (supply chain), ADR-0010 #4, ADR-0018 (R-065).

## 1. Image signing — cosign, keyless (OIDC)

- Every image is signed with **cosign keyless**: the CI job's **GitHub OIDC identity** is
  certified by **Fulcio** (short-lived cert) and the signature is logged in the **Rekor**
  transparency log. **No cosign private key exists** — nothing to leak or rotate.
- The signing identity is `token.actions.githubusercontent.com` + the repo/workflow `sub`.
  Verification pins that identity (`--certificate-identity-regexp` + `--certificate-oidc-issuer`),
  so only images built by *our* pipeline verify. See `vars.COSIGN_CI_IDENTITY_REGEXP`.

## 2. SBOM policy

- A **CycloneDX** SBOM is generated by **Syft** on every build (CI stage 8) and attached to
  the image as a **cosign attestation** (`--type cyclonedx`).
- SBOM **generation failure blocks** the build (docs/10 §2). The SBOM is retained ≥ 1 year with
  the signed release image as compliance evidence (docs/10 §3 retention).

## 3. SLSA provenance

- **Target: SLSA v1, Build L3** (docs/10 §3). Provenance is emitted via
  `actions/attest-build-provenance` and pushed to the registry as an attestation, binding the
  image digest to the builder, source commit, and build parameters.
- Provenance is **verified at admission** — an image that cannot prove it was built by our
  pipeline is rejected.

## 4. Admission control (the enforcement point)

In-cluster (Kyverno / OPA Gatekeeper) the following MUST all hold or the pod is **denied**
(docs/10 §3):

1. **Signature verifies** against the pinned CI OIDC identity (cosign).
2. **SLSA provenance** attestation verifies for the digest.
3. **Policy compliance** — the [`../policies`](../policies) rules (no `:latest`, limits set,
   runAsNonRoot, read-only root FS, NetworkPolicy present).
4. **Rollback-proof label present** — the `Rollback PROVEN` metadata (run id + measured restore
   time) from CI/CD (docs/10 §3 proven-rollback gate, §4.1). *A rollback that was never run is
   not a rollback.*

> The registry stores **immutable digests** (tag = git SHA); Helm values pin **digests, not
> tags**, so what admission verifies is exactly what runs (docs/10 §3).
