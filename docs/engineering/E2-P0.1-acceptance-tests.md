# E2 — P0.1 Acceptance Test Specification & Definition of Done

**Status:** 🟢 Ratified acceptance spec · **Owner:** QA / SRE Lead · **Depends on:** E1 Engineering Specification (sibling), [10 Deployment Architecture](../10-deployment-architecture.md), [13 Implementation Roadmap](../13-implementation-roadmap.md), [P0.1 Delivery Report](../../PHASE-P0.1-REPORT.md)

> **Normative language.** RFC-2119 keywords — **MUST**, **MUST NOT**, **SHOULD**, **MAY** — mark requirements. A test that a deliverable **MUST** pass is merge/exit-blocking; a **SHOULD** is a strong default with a documented-exception path.
>
> **Scope.** This spec makes the P0.1 exit gate — *"infrastructure deploys automatically, idempotently; CI passes; rollback tested"* ([13 P0.1](../13-implementation-roadmap.md)) — **measurable**. It covers the platform foundation only: governance, CI, Terraform, Kubernetes/GitOps, the `platform-hello` canary, supply-chain security, rollback, and observability. **Zero** business / commerce / AI / auth logic is in scope (there is none to test yet).
>
> **Terminology convention.** Delivery semantics are described as **effectively-once** with idempotent consumers; reconciliation ordering is by causal/event order, never by a network-supplied wall-clock. (These conventions are inherited from the certified docs and are enforced by the doc-consistency lint.)

---

## 1. How to read this

Every acceptance test (AT) is written so a reviewer — or a CI job — can run it and get an unambiguous pass/fail. Each carries six fields:

| Field | Meaning |
|-------|---------|
| **ID** | `AT-P01-NN` — stable identifier, cited by the Definition of Done (§10) and the exit-gate checklist (§11). |
| **Given / When / Then** | The precondition, the action, and the observable outcome (behaviour-driven form). |
| **Command / observation** | The *exact* command to run or artifact to inspect. Copy-pasteable where the environment allows. |
| **Pass criterion** | The single measurable condition that decides pass/fail. No judgement calls. |
| **Evidence artifact** | What the tester captures and files against the exit gate (a CI run URL, a log excerpt, a signed report, a screenshot). |
| **Env** | `static` = verifiable now, in this repo, with no cloud; `live` = requires the GitHub org + AWS account (see the honesty note, §12). |

A **fail-closed** test additionally seeds a *known violation* and asserts the pipeline **blocks** — proving the gate has teeth, not just that the happy path is green. Fail-closed tests are marked 🔒.

**Traceability.** Each AT cites the certified source it enforces so a change to the architecture surfaces the tests it invalidates. Ordering, stage names, and thresholds are taken verbatim from [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml), [10 Deployment Architecture](../10-deployment-architecture.md), and the [P0.1 Delivery Report](../../PHASE-P0.1-REPORT.md).

## 2. Repo & governance

### AT-P01-01 — Every directory documents its purpose
- **Given** the monorepo tree.
- **When** a reviewer enumerates every directory that contains tracked files.
- **Then** each such directory **MUST** contain a `README.md` stating purpose · owner · dependencies.
- **Command:** `bash scripts/verify.sh` (governance-README check), or manually:
  ```bash
  # every dir with tracked files must ship a README.md
  comm -23 \
    <(git ls-files | xargs -n1 dirname | sort -u) \
    <(git ls-files '*/README.md' 'README.md' | xargs -n1 dirname | sort -u)
  ```
- **Pass criterion:** the diff is **empty** (0 undocumented directories). The report claims **53 governance READMEs across 204 files**; the count MUST be ≥ that and cover 100% of tracked directories.
- **Evidence:** `verify.sh` output pasted into the exit record; the empty `comm` diff.
- **Env:** static.

### AT-P01-02 — CODEOWNERS covers every path
- **Given** [`.github/CODEOWNERS`](../../.github/CODEOWNERS).
- **When** every top-level path and every governance-sensitive path (`infrastructure/**`, `.github/**`, `docs/**`, `services/**`, `scripts/**`) is matched against the CODEOWNERS globs.
- **Then** there **MUST** be no path that matches **no** owner rule (a catch-all `*` fallback owner MUST exist, and money/infra/security paths MUST have a more specific owner than the fallback).
- **Command:** GitHub's own linter (`gh api repos/:owner/:repo/codeowners/errors`) on a live repo; statically, a coverage script walking `git ls-files` against the CODEOWNERS patterns.
- **Pass criterion:** `codeowners/errors` returns **0 errors**; the static walk reports **0 unowned paths**.
- **Evidence:** the `codeowners/errors` JSON (live) and/or the static coverage report.
- **Env:** static (pattern coverage) + live (GitHub's authoritative validator).

### AT-P01-03 — Branch protection blocks unreviewed / failing merges 🔒
- **Given** the branch-protection intent in [`infrastructure/github/branch-protection.yml`](../../infrastructure/github/branch-protection.yml) applied to `main`.
- **When** (a) a PR is opened with a **failing** `ci-gate`, and separately (b) a PR is opened with **0 approvals** (or without the required CODEOWNER approval).
- **Then** the merge button **MUST** be disabled in both cases; force-push and branch deletion on `main` **MUST** be denied.
- **Command (live):**
  ```bash
  gh api repos/:owner/:repo/branches/main/protection | \
    jq '{checks:.required_status_checks.contexts, reviews:.required_pull_request_reviews}'
  # then attempt: gh pr merge <failing-pr>   → expected: rejected
  ```
- **Pass criterion:** `required_status_checks.contexts` **MUST** contain `ci-gate`; `required_pull_request_reviews.required_approving_review_count` **MUST** be ≥ 1 with `require_code_owner_reviews: true`; both seeded merge attempts are **rejected**.
- **Evidence:** the protection JSON; screenshots/API responses of the two blocked merges.
- **Env:** static (intent file review) + **live** (enforcement).

## 3. CI pipeline — the 18-stage fail-closed gate

The pipeline in [`ci.yml`](../../.github/workflows/ci.yml) is one required check, `ci-gate`, fed by 18 jobs chained with `needs:`. The following ATs verify **presence + ordering** once, then **fail-closed** on a seeded violation per marquee stage.

### AT-P01-04 — All 18 stages present, ordered, and gated by a single required check
- **Given** `ci.yml`.
- **When** the workflow is parsed and the `needs:` graph is walked.
- **Then** the 18 stages **MUST** appear in the mandated order — Formatting → Lint → Unit → SAST → Secrets → Dependency → Container-scan → SBOM → TF-validate → TF-plan → Policy → Doc-lint → Mermaid → Build → Deploy-staging → Smoke → Rollback-proven → **`ci-gate`** — and `ci-gate` **MUST** `needs:` every gate and **MUST** fail if any dependency is not `success`.
- **Command:** `python -c "import yaml,sys; d=yaml.safe_load(open('.github/workflows/ci.yml')); print(list(d['jobs']))"` and inspect `ci-gate.needs` + its assert step.
- **Pass criterion:** 18 jobs present in order; top-level `permissions: {}` (deny-by-default); `ci-gate` blocks on any non-`success` result (`grep -vqx "success"` logic present).
- **Evidence:** job list; the `ci-gate` step body.
- **Env:** static.

**Per-stage pass/seeded-fault matrix.** Each row is a fail-closed assertion; the AT column is the seeded-violation test that proves the block.

### AT-P01-05 — A broken unit test blocks the gate 🔒
- **Given** the `platform-hello` Go suite (root, `/healthz`, `/readyz` cold/warm, route wiring).
- **When** a test assertion is deliberately broken on a branch.
- **Then** stage 3 **MUST** go red and `ci-gate` **MUST** block the merge.
- **Command:** `go test ./...` in `services/platform-hello` locally; observe the CI `3 · Unit tests` job on the branch.
- **Pass criterion:** unit stage red; `ci-gate` = failure; merge disabled. Revert restores green.
- **Evidence:** failing CI run URL; the red-then-green pair.
- **Env:** static (local `go test`) + live (gate enforcement).

### AT-P01-06 — SAST high/critical finding blocks 🔒
- **Given** the CodeQL + Semgrep configuration (`--config p/owasp-top-ten`, `--error`).
- **When** a branch introduces a Semgrep/CodeQL high-severity pattern (e.g. a command-injection sink).
- **Then** stage 4 **MUST** fail closed.
- **Command:** local `semgrep --config .semgrep --config p/owasp-top-ten --error .`; CI `4 · SAST` job.
- **Pass criterion:** non-zero exit on the seeded sink; SARIF uploaded to the security tab; gate blocked.
- **Evidence:** Semgrep/CodeQL SARIF; failing run URL.
- **Env:** static (local Semgrep) + live (CodeQL DB).

### AT-P01-07 — A planted secret fails gitleaks 🔒
- **Given** the `5 · Secrets scan` job with `fetch-depth: 0` (full history).
- **When** a branch commits a syntactically valid but fake credential (e.g. `AKIA...` + secret).
- **Then** gitleaks **MUST** detect it and fail the job; the report **MUST NOT** be uploaded as an artifact (no secret echo).
- **Command:** local `gitleaks detect --source . --redact`; CI `5 · Secrets scan` job.
- **Pass criterion:** gitleaks exits non-zero on the planted secret; `GITLEAKS_ENABLE_UPLOAD_ARTIFACT=false` confirmed; gate blocked. Removing the secret restores green.
- **Evidence:** redacted gitleaks output; failing run URL.
- **Env:** static (local gitleaks) + live.

### AT-P01-08 — Critical CVE / disallowed license blocks 🔒
- **Given** the `6 · Dependency & license` job (osv-scanner + license allowlist).
- **When** a dependency with a known fixable **critical** CVE, or a license outside the allowlist (e.g. GPL in a proprietary tree), is added.
- **Then** stage 6 **MUST** block.
- **Command:** `osv-scanner --recursive ./`; the license-allowlist step against the dependency tree.
- **Pass criterion:** osv exits non-zero on the seeded CVE; the license gate rejects the disallowed license.
- **Evidence:** osv-scanner report; license-gate log.
- **Env:** static (osv on the lockfiles) + live (full tree).

### AT-P01-09 — Container scan blocks a vulnerable image 🔒
- **Given** the `7 · Container scan` job (Trivy, `severity: CRITICAL,HIGH`, `ignore-unfixed: true`, `exit-code: 1`).
- **When** the `platform-hello` image is built against a base with a fixable CRITICAL/HIGH CVE.
- **Then** Trivy **MUST** fail the job; the SARIF **MUST** still upload (auditability on block).
- **Command:** `trivy image nexus/platform-hello:<sha> --severity CRITICAL,HIGH --ignore-unfixed --exit-code 1`.
- **Pass criterion:** non-zero exit on the seeded CVE; SARIF present in the security tab.
- **Evidence:** Trivy SARIF; failing run URL.
- **Env:** live (needs a built image) — statically, config is asserted (`exit-code: "1"`).

### AT-P01-10 — A `:latest` image or a limits-less pod fails policy 🔒
- **Given** the OPA/conftest policies in [`infrastructure/security/policies`](../../infrastructure/security/policies) (`deny_latest_image.rego`, `require_resource_limits.rego`, `deny_public_s3.rego`, `deny_open_money_sg.rego`, `require_tags.rego`) and their unit tests in [`tests/policy`](../../tests/policy).
- **When** a manifest pins `image: …:latest`, or omits `resources.limits`, is fed to conftest.
- **Then** `conftest test` **MUST** deny it; `conftest verify` **MUST** confirm the policies' own unit tests pass first (a broken rule cannot silently pass).
- **Command:**
  ```bash
  conftest verify --policy infrastructure/security/policies --policy tests/policy
  conftest test <seeded-manifest.yaml> --policy infrastructure/security/policies --all-namespaces
  ```
- **Pass criterion:** `verify` green (rule unit tests pass); `test` returns a **deny** for the `:latest` manifest **and** for the limits-less manifest; a clean manifest passes.
- **Evidence:** conftest output for verify + both seeded manifests.
- **Env:** static (conftest runs locally / in CI without cloud).

### AT-P01-11 — A doc-lint violation fails the build 🔒
- **Given** [`scripts/doc_consistency_lint.py`](../../scripts/doc_consistency_lint.py).
- **When** a banned/retired term, a broken relative link, or a dangling intra-repo anchor is introduced into any `docs/**` file.
- **Then** stage 12 **MUST** exit non-zero.
- **Command:** `python scripts/doc_consistency_lint.py`.
- **Pass criterion:** on the current tree the lint prints `PASS`; on the seeded violation it prints `FAIL` with the offending file:line and exits 1. The report states **doc-lint GREEN across the certified set** — that baseline MUST hold.
- **Evidence:** the PASS line (baseline) and the FAIL line (seeded) side by side.
- **Env:** static.

### AT-P01-12 — An invalid Mermaid diagram fails the build 🔒
- **Given** [`scripts/mermaid_validate.py`](../../scripts/mermaid_validate.py).
- **When** a fenced mermaid block (triple-backtick + `mermaid`) is malformed — an unknown diagram type or an unbalanced fence.
- **Then** stage 13 **MUST** fail.
- **Command:** `python scripts/mermaid_validate.py`.
- **Pass criterion:** clean tree passes (report: **69 diagrams valid**); the seeded corruption fails.
- **Evidence:** validator output (baseline + seeded).
- **Env:** static.

### AT-P01-13 — CI holds no static cloud credentials (OIDC-only, least privilege)
- **Given** `ci.yml`.
- **When** the workflow is audited for credential handling.
- **Then** there **MUST** be no static AWS keys; AWS access **MUST** be via `id-token: write` + `configure-aws-credentials` (OIDC); top-level `permissions: {}` with each job widening the minimum; every `uses:` pinned to a 40-char commit SHA.
- **Command:** `grep -nE 'aws-access-key|secret-access-key|AKIA' .github/workflows/*.yml` (expect none); inspect `id-token`/`role-to-assume` usage; `grep -oE 'uses: [^ ]+@[0-9a-f]{40}' ci.yml | wc -l` vs total `uses:`.
- **Pass criterion:** 0 static-key references; OIDC roles referenced via `vars.*` (never `secrets` for account IDs); every action SHA-pinned.
- **Evidence:** the grep results; the OIDC-trust contract in [`infrastructure/github/oidc-trust.md`](../../infrastructure/github/oidc-trust.md).
- **Env:** static (audit) + live (a PR-ref token cannot assume an apply/prod role — AT-P01-16).

## 4. Terraform (IaC)

### AT-P01-14 — Format is canonical
- **Given** the Terraform estate under `infrastructure/terraform`.
- **When** `terraform fmt -check -recursive` runs.
- **Then** it **MUST** exit 0 (no reformatting needed).
- **Command:** `terraform -chdir=infrastructure/terraform fmt -check -recursive`.
- **Pass criterion:** exit 0, empty output.
- **Evidence:** command output.
- **Env:** static.

### AT-P01-15 — Every module validates in isolation 🔒
- **Given** the 8 primitives + `region-stack` + `global` + 3 env roots.
- **When** each module is initialised offline and validated.
- **Then** each **MUST** pass `terraform validate` with `-backend=false` (no hidden cross-module coupling); a seeded HCL/type error **MUST** fail.
- **Command:**
  ```bash
  for m in infrastructure/terraform/modules/*/; do
    terraform -chdir="$m" init -backend=false -input=false >/dev/null
    terraform -chdir="$m" validate
  done
  ```
- **Pass criterion:** all 9 modules + `global` + 3 envs report **"Success! The configuration is valid."** The report claims all pass; that MUST hold. A seeded type error fails validate.
- **Evidence:** per-module validate output; the `9 · Terraform validate` CI job.
- **Env:** static.

### AT-P01-16 — `plan` on dev/staging succeeds via OIDC (read-only)
- **Given** the `10 · Terraform plan` job assuming `vars.AWS_TF_PLAN_ROLE_ARN` (read-only) through OIDC.
- **When** the pipeline runs `terraform init && terraform plan` against `envs/staging` (and, on merge, `envs/dev`).
- **Then** the plan **MUST** complete using short-lived federated credentials with **no** static keys, and a PR-ref token **MUST NOT** be able to assume an apply/prod role.
- **Command (live):** trigger the `tf-plan` job; confirm `terraform show -json tfplan.binary > tfplan.json` succeeds and the JSON feeds the policy gate.
- **Pass criterion:** plan exits 0; role-session is the read-only plan role; an apply attempt from a PR ref is denied by the trust policy.
- **Evidence:** the tf-plan job log; the uploaded `tfplan-json` artifact; a denied-assume-role CloudTrail entry.
- **Env:** **live** (needs the AWS account + OIDC provider from the `global` landing zone).

### AT-P01-17 — A second apply is a no-op (idempotency) 🔒
- **Given** a `dev` environment already applied from Git + pinned inputs.
- **When** `terraform apply` runs a **second** time with no code change.
- **Then** the plan **MUST** report **0 to add, 0 to change, 0 to destroy** (a genuine no-op) — this is the idempotency proof called out in the [P0.1 exit gate](../../infrastructure/README.md).
- **Command (live):**
  ```bash
  cd infrastructure/terraform/envs/dev
  terraform apply -auto-approve            # first apply (bootstrap)
  terraform plan -detailed-exitcode        # second: exit 0 == no-op, 2 == drift
  ```
- **Pass criterion:** the second `plan -detailed-exitcode` returns **exit code 0** ("No changes"). Any non-empty plan fails the test and raises a drift ticket.
- **Evidence:** the "No changes. Your infrastructure matches the configuration." plan output.
- **Env:** **live** (requires a real AWS apply — cannot be executed in the authoring environment).

### AT-P01-18 — No secret material in state
- **Given** the remote state (S3 + DynamoDB lock, per env-account-region, KMS-encrypted) and the `security/` module (secret *containers* only, no `secret_version`).
- **When** the state and plan JSON are scanned for plaintext credentials.
- **Then** there **MUST** be no plaintext secret, account-embedded credential, or `.tfvars` value committed to Git or emitted into state; the Aurora master credential **MUST** be AWS-managed in Secrets Manager.
- **Command:** `gitleaks detect --source .` over the repo (0 findings); on live state: `terraform show -json | jq` audited for secret attributes; confirm no `*.tfvars` tracked (`git ls-files '*.tfvars'` empty).
- **Pass criterion:** 0 secrets in Git; 0 plaintext secrets in state; state bucket is KMS-encrypted + versioned; no tracked `.tfvars`.
- **Evidence:** gitleaks report; state-scan output; bucket encryption config.
- **Env:** static (Git/secret scan) + live (state inspection).

- **Evidence:** rendered manifest excerpt; dry-run output.
- **Env:** static (helm template + client dry-run; no cluster needed).

### AT-P01-20 — A pod without resource limits is rejected 🔒
- **Given** the admission policy (Kyverno/Gatekeeper in-cluster; conftest `require_resource_limits.rego` in CI).
- **When** a pod manifest omitting `resources.limits` (or with `runAsNonRoot: false`, or no NetworkPolicy) is submitted.
- **Then** admission **MUST** reject it; the same manifest **MUST** be denied by conftest in CI (defense in depth).
- **Command:** `conftest test <no-limits-pod.yaml> --policy infrastructure/security/policies`; on a live cluster `kubectl apply -f <no-limits-pod.yaml>` (expect admission webhook denial).
- **Pass criterion:** conftest returns a deny; live admission returns an error citing the policy; a compliant pod is admitted.
- **Evidence:** conftest deny output; the admission-webhook rejection message.
- **Env:** static (conftest) + live (admission webhook).

### AT-P01-21 — ArgoCD syncs staging
- **Given** the staging ArgoCD Application ([`infrastructure/kubernetes/overlays/staging/argocd-application.yaml`](../../infrastructure/kubernetes/overlays/staging/argocd-application.yaml)) watching the config repo.
- **When** the `15 · Deploy staging` job opens the digest-bump PR and it merges to the staging env branch.
- **Then** ArgoCD **MUST** pull and reconcile the change (CI holds no cluster creds); the Application **MUST** report **Synced / Healthy**.
- **Command (live):** `argocd app get nexus-platform-hello-staging -o json | jq '{sync:.status.sync.status, health:.status.health.status}'`.
- **Pass criterion:** `sync.status == "Synced"` and `health.status == "Healthy"` on the bumped digest; drift auto-heals on staging.
- **Evidence:** ArgoCD app status JSON / UI screenshot; the digest-bump PR.
- **Env:** **live** (needs the cluster + ArgoCD + config repo).

## 6. platform-hello (the pipeline canary)

### AT-P01-22 — The canary deploys end-to-end
- **Given** the signed `platform-hello` image and its chart.
- **When** ArgoCD reconciles it into staging.
- **Then** the Deployment **MUST** reach ready replicas with no crash-loop.
- **Command (live):** `kubectl -n platform get deploy platform-hello -o wide`.
- **Pass criterion:** desired == available replicas; 0 restarts attributable to the app; pod passes admission (signed image, limits, non-root).
- **Evidence:** `kubectl get` output; ArgoCD health.
- **Env:** live.

### AT-P01-23 — `/healthz` returns 200 (liveness)
- **Given** the running canary on port 8080.
- **When** the liveness endpoint is probed.
- **Then** it **MUST** return HTTP 200 while the process is up.
- **Command:** `curl -s -o /dev/null -w '%{http_code}' localhost:8080/healthz` (local) / against the staging URL (live).
- **Pass criterion:** `200`. Locally reproducible now via the build-and-run steps in the [service README](../../services/platform-hello/README.md).
- **Evidence:** curl status; the `16 · Smoke` job log.
- **Env:** static (local run) + live (staging).

### AT-P01-24 — `/readyz` gates traffic (503 cold → 200 warm)
- **Given** the readiness endpoint, which returns 200 only after warm-up **and** the dependency-check stub passes.
- **When** the pod is probed immediately after start, then after warm-up.
- **Then** it **MUST** return **503 while cold / dependencies-unhealthy** and **200 once ready** — so the Service adds the pod to endpoints only when ready (traffic gating + canary-analysis backing).
- **Command:** poll `curl -s -w '%{http_code}' localhost:8080/readyz` across the warm-up window; the Go suite already asserts cold vs warm.
- **Pass criterion:** observed transition 503 → 200; a pod never receives traffic while `/readyz` is 503.
- **Evidence:** the poll transcript; the `readyz cold/warm` unit test result.
- **Env:** static (local + unit test) + live (endpoint gating).

### AT-P01-25 — `/metrics` is scraped by Prometheus
- **Given** golden-signal metrics on the isolated port 9090 (`platform_hello_http_requests_total`, `..._request_duration_seconds`, `..._build_info`) and a ServiceMonitor from the library chart.
- **When** Prometheus (see [`infrastructure/monitoring`](../../infrastructure/monitoring)) discovers the target.
- **Then** the target **MUST** be `up == 1` and the three metric families **MUST** be queryable.
- **Command:** local `curl -s localhost:9090/metrics | grep platform_hello`; live PromQL `up{job="platform-hello"}` and `platform_hello_http_requests_total`.
- **Pass criterion:** exposition contains all three families locally; `up == 1` and non-empty series in Prometheus.
- **Evidence:** metrics exposition excerpt; a Prometheus query screenshot.
- **Env:** static (local `/metrics`) + live (scrape).

### AT-P01-26 — A trace appears in Tempo
- **Given** the OTel-traced `/` route (server span + child span via `otelhttp`) and the OTel Collector in the `observability` namespace.
- **When** a request hits `/` on staging.
- **Then** the corresponding trace **MUST** be retrievable in Tempo with the server span and its child span, propagated trace/span IDs intact.
- **Command (live):** issue a request carrying a known trace-id; query Tempo by that trace-id.
- **Pass criterion:** the trace is found in Tempo with ≥ 2 spans (server + child) for the canary; the OTel Collector's absence disables export only — it never blocks serving.
- **Evidence:** the Tempo trace permalink (an exit-gate artifact, §11).
- **Env:** **live** (needs the observability backend).

### AT-P01-27 — Logs land in Loki
- **Given** structured logs shipped to the observability domain (isolated failure domain).
- **When** the canary serves requests on staging.
- **Then** its logs **MUST** be queryable in Loki, correlated by trace-id where present.
- **Command (live):** LogQL `{app="platform-hello"}` over the request window.
- **Pass criterion:** non-empty log stream for the canary; a log line carries the same trace-id as its Tempo trace.
- **Evidence:** Loki query result / screenshot.
- **Env:** **live**.

## 7. Security & supply chain

### AT-P01-28 — An SBOM is produced 🔒
- **Given** the `8 · SBOM` job (Syft → CycloneDX).
- **When** the pipeline runs.
- **Then** `sbom.cyclonedx.json` **MUST** be generated and uploaded as an artifact; removing the SBOM step **MUST** fail the build (SBOM is a required output).
- **Command:** `syft dir:. -o cyclonedx-json > sbom.cyclonedx.json`; confirm the CI artifact `sbom-cyclonedx`.
- **Pass criterion:** valid CycloneDX JSON produced and retained; it is later attached to the image as a cosign attestation (AT-P01-29).
- **Evidence:** the SBOM artifact.
- **Env:** static (Syft on the source) + live (attestation attach).

### AT-P01-29 — Image is cosign-signed and verifiable
- **Given** the `14 · Build · sign · attest` job (cosign keyless via Fulcio/Rekor, SLSA provenance, CycloneDX attestation), which runs on `main` only.
- **When** the release image is built and pushed to ECR by **digest**.
- **Then** `cosign verify` against the platform's OIDC identity **MUST** succeed, and the SBOM + SLSA provenance attestations **MUST** verify.
- **Command (live):**
  ```bash
  cosign verify \
    --certificate-identity-regexp '<ci-oidc-identity>' \
    --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
    "$ECR_REGISTRY/nexus-platform-hello@<digest>"
  cosign verify-attestation --type cyclonedx ...
  ```
- **Pass criterion:** `cosign verify` returns a valid signature with a Rekor entry; the CycloneDX + SLSA-provenance attestations verify against the digest.
- **Evidence:** the `cosign verify` output (an exit-gate artifact, §11); the Rekor log index.
- **Env:** **live** (needs ECR + Fulcio/Rekor).

### AT-P01-30 — An unsigned image is rejected by admission 🔒
- **Given** the Kyverno/Gatekeeper `cosign verify` admission policy.
- **When** a pod referencing an **unsigned** (or provenance-less, or policy-violating) image is submitted.
- **Then** admission **MUST** reject it — enforcing "unsigned images MUST NOT run".
- **Command (live):** `kubectl apply -f <pod-with-unsigned-image.yaml>` (expect denial); a signed digest is admitted.
- **Pass criterion:** unsigned/unattested image → admission denied; signed+attested digest → admitted.
- **Evidence:** the admission rejection message; the successful signed-image admission.
- **Env:** **live**.

### AT-P01-31 — Zero High/Critical vulnerabilities
- **Given** the SAST, dependency, secret, and container scan gates.
- **When** the full pipeline runs on the P0.1 tree.
- **Then** the aggregate High/Critical finding count across all scanners **MUST** be **0** (the P0.7 verified condition, wired from P0.1). Time-boxed, security-owner-approved, expiring suppressions are the only exception path.
- **Command:** review the SARIF from CodeQL/Semgrep/Trivy + osv-scanner + gitleaks results.
- **Pass criterion:** 0 unsuppressed High/Critical findings; any suppression carries an owner + expiry.
- **Evidence:** the consolidated scan summary; the security tab.
- **Env:** static (source-level scans) + live (image scans).

## 8. Rollback

### AT-P01-32 — A bad deploy is auto-rolled-back within the stated max time 🔒
- **Given** the `17 · Rollback PROVEN` gate and the per-change-type rollback table ([10 §4.1](../10-deployment-architecture.md)): application-code rollback max time **seconds (canary abort) → ≤ 5 min (Git-revert reconcile)**.
- **When** a deliberately unhealthy `platform-hello` version is promoted to a preview/staging canary (e.g. `/readyz` forced to 503 or error-rate injected).
- **Then** Argo Rollouts' AnalysisTemplate **MUST** detect the SLO breach, **auto-abort**, and revert to the last-good ReplicaSet **without a human in the revert path**; the gate **MUST** emit a rollback-proof label `{run_id, restore_seconds}` and **MUST** fail closed if `restore_seconds` exceeds the max.
- **Command (live):** run the rollback drill in the preview env; capture the measured restore time; confirm an incident stub is auto-opened.
- **Pass criterion:** service restored to last-good within the stated max (≤ 5 min for the Git-revert path; seconds for canary abort); rollback-proof label present; the CD proven-rollback gate reads it before any promotion. A drill where restore exceeds max **MUST** block promotion.
- **Evidence:** the rollback drill record (measured `restore_seconds`, run id); the auto-filed incident stub — an exit-gate artifact (§11).
- **Env:** **live** (needs a preview/staging cluster + Argo Rollouts + metrics; wired but not yet drilled per the report).

## 12. Honesty note — what is verifiable now vs. only in a live environment

Per the [Delivery Report §5](../../PHASE-P0.1-REPORT.md), the P0.1 scaffold is **code-complete, internally consistent, and locally validated**; three classes of test are **execution-dependent** and cannot be run in the authoring environment.

**Statically verifiable now (no cloud, no GitHub org):**

- Repo/governance structure — AT-P01-01, and the CODEOWNERS *pattern coverage* half of AT-P01-02.
- CI presence + ordering + least-privilege + SHA-pinning audit — AT-P01-04, AT-P01-13.
- Doc-lint and Mermaid gates (baseline + seeded fault) — AT-P01-11, AT-P01-12.
- Policy-as-code (conftest `verify` + seeded `:latest`/limits-less denials) — AT-P01-10, and the conftest half of AT-P01-20.
- Terraform `fmt -check` + per-module `validate` (+ seeded HCL error) — AT-P01-14, AT-P01-15.
- Secret hygiene of the tree (gitleaks over Git, no tracked `.tfvars`) — the static half of AT-P01-07, AT-P01-18.
- SBOM generation over source, Syft/Semgrep/osv on the local tree, `go test`, `helm template` dry-run, local `/healthz`/`/readyz`/`/metrics` — AT-P01-05, AT-P01-06, AT-P01-08, AT-P01-19, AT-P01-23, AT-P01-24, AT-P01-25 (local), AT-P01-28.

**Executable only in a live GitHub + AWS environment:**

- **Apply-idempotency (AT-P01-17)** — requires a real `terraform apply` in your AWS account; the no-op second plan is the proof and can only exist once state exists.
- **Live CI pass (AT-P01-03 enforcement, AT-P01-09, AT-P01-16, AT-P01-29, AT-P01-31 image half)** — needs the GitHub org, the OIDC↔AWS trust from the `global` landing zone, ECR, and the hosted scanners (CodeQL/Trivy) + Fulcio/Rekor. The workflows parse and are green-by-design; a real run needs these services.
- **Rollback drill (AT-P01-32)** — the `Rollback PROVEN` gate is wired, but the drill needs a preview/staging cluster with Argo Rollouts + live metrics to measure `restore_seconds`. It is **not** yet drilled.
- **GitOps + admission + observability (AT-P01-21, AT-P01-22, AT-P01-26, AT-P01-27, AT-P01-30, AT-P01-33, AT-P01-34)** — need the EKS cluster, ArgoCD, Kyverno, and the Grafana/Tempo/Loki/Prometheus backend.

**Blockers to a first live pass** (from the report's risk register): placeholder OIDC role ARNs / account IDs (filled from `global`/`security` Terraform outputs at bootstrap), placeholder pinned action SHAs (verify + Renovate — a wrong SHA fails closed), and the `@nexus/*` GitHub teams that CODEOWNERS + prod approvers depend on. Until these exist the pipeline **fails closed** — which is the safe default.

**Bottom line.** This spec does **not** declare the P0.1 exit gate passed. It declares it **ready to pass**: every static test above is runnable today, and every live test has an exact command and an evidence artifact, so the gate can be closed deterministically once items 1–6 of the report's *Remaining work* are done in your environment.
